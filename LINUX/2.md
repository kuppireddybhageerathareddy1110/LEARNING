# Linux File Permissions (In Depth)

Linux uses a permission system to control **who can access files and directories** and **what actions they can perform**. This is one of the most important Linux concepts for SRE, DevOps, and System Administration interviews.

---

# Why are file permissions important?

Permissions help to:

* Protect sensitive files
* Prevent unauthorized access
* Improve system security
* Control user actions
* Prevent accidental deletion or modification

Example:

```
salary.xlsx
```

Only HR should read it.

```
website_config.conf
```

Only the administrator should modify it.

---

# Every file has three things

Every file has:

1. Owner (User)
2. Group
3. Others

Example

```
-rwxr-xr--
```

```
Owner     Group     Others
```

# Changing Permissions

Using numeric mode

```bash
chmod 755 file.sh
```

Using symbolic mode

Add execute

```bash
chmod +x file.sh
```

Remove write

```bash
chmod -w file.txt
```

Add read

```bash
chmod +r file.txt
```

Owner only

```bash
chmod u+x file.sh
```

Group

```bash
chmod g+w file.txt
```

Others

```bash
chmod o-r file.txt
```

All

```bash
chmod a+x file.sh
```

Owner


Only group


# Special Permissions (Advanced)

## Sticky Bit (`t`)

Common on `/tmp`.

```
drwxrwxrwt
```

Everyone can create files, but users can delete **only their own** files.

Check:

```bash
ls -ld /tmp
```

---

## Setuid (`s`)

When an executable has the setuid bit, it runs with the **owner's privileges** instead of the user's.

Example:

```
-rwsr-xr-x
```

A common example is the `passwd` command, which needs temporary root privileges to update password information.

---

## Setgid (`s`)

On directories, new files inherit the directory's group instead of the creator's primary group.

Useful for shared project directories.

Example:

```
drwxrwsr-x
```

# Interview Questions

### 1. What does `chmod 755` mean?

Owner has **rwx**, group has **r-x**, others have **r-x**.

---

### 2. Difference between `644` and `755`?

* **644:** Owner can read/write; group and others can only read. Suitable for regular files.
* **755:** Owner can read/write/execute; group and others can read/execute. Suitable for executable files and directories.

---

### 3. Why shouldn't you use `777`?

It grants read, write, and execute permissions to everyone, making the file or directory vulnerable to unauthorized changes or malicious use.

---

### 4. What is the difference between file and directory execute permission?

* **File:** Allows the file to be executed as a program or script.
* **Directory:** Allows users to enter (`cd`) and access items inside the directory.

---

### 5. Explain the output below:

```bash
-rwxr-xr--
```

* `-` → Regular file
* Owner: `rwx` → Read, write, execute
* Group: `r-x` → Read, execute
* Others: `r--` → Read only

---

## 30-Second Interview Answer

> "Linux file permissions control who can access files and directories. Each file has an owner, a group, and others, with three permission types: read (4), write (2), and execute (1). Permissions are displayed using `ls -l`, such as `-rwxr-xr--`. Numeric values like `755` represent `rwxr-xr-x`, where the owner has full access and group and others have read and execute permissions. Permissions are changed using `chmod`, ownership with `chown`, and group ownership with `chgrp`. Linux also supports special permissions like setuid, setgid, and the sticky bit for advanced access control."
