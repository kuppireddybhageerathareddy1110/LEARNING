From the `iostat -x 1 3` output:

* **CPU iowait = 2.66%** (not very high)
* **Disk utilization (%util) = 28.60%**
* **Writes = 575 w/s (~206 MB/s)**
* Large write activity indicates **a process is continuously writing to disk**.

The expected solved state shows:

* CPU idle ~79%
* System CPU ~0.2%
* Much lower disk activity.

### Most likely fix

Find and stop the process generating excessive disk writes.

Run:

```bash
iotop -o
```

or

```bash
pidstat -d 1
```

If `iotop` is unavailable:

```bash
lsof | grep deleted
```

and

```bash
ps aux --sort=-%cpu
```

If you identify a runaway process, stop it:

```bash
kill <PID>
```

or

```bash
kill -9 <PID>
```

If it's a service:

```bash
systemctl stop <service-name>
```

Then verify:

```bash
iostat -x 1 3 | tail -8
```

---

Since this is a **Crucible SRE lab**, the excessive writes are often caused by:

* a `dd` process,
* `yes > file`,
* `cat /dev/zero > file`,
* or a logging process.

To identify it quickly, run:

```bash
iotop -oPa
```

or

```bash
ps aux | grep -E "dd|yes|cat"
```

If you can paste the outputs of:

```bash
ps aux --sort=-%cpu | head -20
```

and

```bash
iotop -oPa
```

| Scenario             | How to Diagnose                                          | Typical Fix                            |
| -------------------- | -------------------------------------------------------- | -------------------------------------- |
| Disk full            | `df -h`, `du -sh /*`, `find / -size +500M`               | Delete/move large files, truncate logs |
| High CPU             | `top`, `htop`, `ps aux --sort=-%cpu`                     | Kill or restart runaway process        |
| High Memory          | `free -h`, `top`, `ps aux --sort=-%mem`                  | Stop memory-hogging process            |
| High Disk I/O        | `iostat -x`, `iotop`, `pidstat -d`                       | Stop excessive writers                 |
| Service Down         | `systemctl status service`                               | `systemctl restart service`            |
| Service Fails        | `journalctl -u service`                                  | Fix configuration and restart          |
| Website Down         | `curl localhost`, `systemctl status nginx/apache2`       | Restart web server, check logs         |
| Port Already in Use  | `ss -tulpn`, `lsof -i :80`                               | Kill conflicting process               |
| DNS Not Working      | `dig`, `nslookup`, `cat /etc/resolv.conf`                | Fix resolver configuration             |
| SSH Failure          | `systemctl status sshd`, `ss -tlnp`                      | Start SSH service, open port 22        |
| Wrong Permissions    | `ls -l`                                                  | `chmod`, `chown`                       |
| Log Files Growing    | `du -sh /var/log`, `journalctl --disk-usage`             | Rotate or truncate logs                |
| Cron Job Failure     | `crontab -l`, `systemctl status cron`                    | Fix cron entry or restart cron         |
| Docker Issue         | `docker ps -a`, `docker logs`, `systemctl status docker` | Restart Docker or container            |
| Network Connectivity | `ip addr`, `ip route`, `ping`, `curl`                    | Fix IP, route, firewall, or DNS        |
